# 일일보육계획안 만들기

## GitHub / Streamlit 배포

실행에 필요한 파일은 `app.py`, `requirements.txt`, `template.hml`, `routine_plans.json`입니다.
이 세 파일을 함께 업데이트하고 Streamlit의 실행 파일은 `app.py`로 지정하세요.
`app1.py`, `make_template.py`, 실제 아동 정보가 있는 샘플 문서는 업로드할 필요가 없습니다.

Streamlit 앱 설정의 Secrets에 다음을 입력하세요. API 키를 GitHub에 올리지 마세요.

```toml
GEMINI_API_KEY = "발급받은 키"
```

기본적으로 계정에서 사용 가능한 정식 Flash 모델을 조회합니다. 모델을 직접 지정하려면
Secrets에 `GEMINI_MODEL = "사용 가능한 모델 ID"`를 추가하세요.
키가 설정되면 사용자는 파일만 올리면 됩니다. 키가 없으면 화면에서 임시 입력할 수 있습니다.

### 유료 우선 → 한도 오류 시 무료 전환

Streamlit Secrets에 아래 두 키를 설정하면 됩니다.

```toml
GEMINI_API_KEY = "기본으로 사용할 유료 프로젝트의 API 키"
GEMINI_FREE_API_KEY = "무료 등급 프로젝트의 API 키"
# 선택: 기본 모델과 보조 모델을 따로 지정할 수 있습니다.
# GEMINI_MODEL = "기본 프로젝트에서 사용할 모델 ID"
# GEMINI_FREE_MODEL = "무료 등급을 지원하는 모델 ID"
```

- 매번 기본 키로 먼저 요청합니다. 자동 선택에서는 사용 가능한 정식 Flash 모델들을 순서대로 시도하며, 모델별 429/404/500/503 오류에서는 다음 모델을 시도합니다.
- 모델을 직접 지정했다면 해당 모델만 사용합니다. 기본 프로젝트에서 후보들을 시도한 뒤 마지막 오류가 429일 때 보조 키로 한 번 전환합니다.
- 실패 화면에는 시도한 모델, HTTP 코드, Google이 제공한 제한 항목과 재시도 대기 시간을 표시합니다. API 키와 원본 오류 전문은 표시하지 않습니다.
- 제목 아래 `2026-09-26-r3`가 보이면 날짜별 생성 수정 버전입니다. 이전 버전이 보인다면 Streamlit이 실행하는 저장소·브랜치·파일과 배포 상태를 확인하세요.
- 모델 목록 조회 중 발생한 429도 같은 방식으로 처리합니다.
- 무료 전환용 키가 없으면 기존 키로 계속 사용하며, 한도 오류 시 설정 안내가 나옵니다.
- 두 프로젝트 모두 한도에 도달하면 중단하고 안내합니다. 키 오류나 잘못된 문서 결과로는 전환하지 않습니다.
- 유료 잔액을 조회하거나 결제를 바꾸는 기능은 아닙니다. 429는 분당 요청/토큰 한도 초과일 수도 있습니다.
- 한도는 **프로젝트 기준**입니다. 같은 프로젝트에서 키만 추가 발급해도 한도는 공유됩니다.
- Google AI Studio에서 보조 키의 프로젝트가 Free 등급인지, 사용할 모델에 무료 할당량이 있는지 확인하세요.
  앱은 키의 요금제를 판별하지 않으므로 보조 키가 유료 프로젝트 소속이면 요금이 발생할 수 있습니다.
- 무료 서비스는 입력·응답의 데이터 처리 조건이 유료 서비스와 다를 수 있습니다. 아동 개인정보를 제거한 자료를 사용하세요.

참고: [Gemini 한도](https://ai.google.dev/gemini-api/docs/rate-limits),
[요금제와 데이터 처리](https://ai.google.dev/gemini-api/docs/billing).

## 사용하는 방법

1. 이번 주 실행주안(.hwp 또는 .hml)을 올립니다.
2. 표준보육과정 사진/PDF와 문체 참고용 일일보육계획안은 '교육 자료·참고 문서 추가'에서 선택적으로 올립니다. 공식 기준의 정확한 세부내용을 반영하려면 교육 자료를 함께 올리세요.
3. **날짜별 계획안 모두 만들기**를 누릅니다. 날짜 입력이나 미리보기 확인 단계는 없습니다.
4. **날짜별 파일 N개 한 번에 저장 (ZIP)**을 누릅니다. ZIP을 풀면 날짜별 .hml 파일이 들어 있습니다.
5. 한글의 **파일 → 열기**로 .hml을 열고 수정합니다. 필요하면 파일 형식을 전체 파일로 선택하세요.
6. 작성된 활동·평가를 확인하고 필요하면 **다른 이름으로 저장 → 한글 문서(.hwp)**로 저장합니다.

실행주안의 실시기간에서 평일 목록을 먼저 계산하고, 날짜별로 AI를 호출합니다.
예: `2026년 9월 1주 (8월 31일 ~ 9월 5일)`이면 월~금 5개 파일을 만듭니다.
토·일은 제외하며, `2일 (수) 휴원`처럼 날짜 옆에 명시된 휴원일도 제외합니다.
한국어 월·일 범위와 `2026.08.31 ~ 2026.09.05` 형태를 지원합니다.
기간을 해석하지 못하면 날짜를 추측하거나 하루치만 성공 처리하지 않고 안내합니다.
도중에 실패하면 같은 접속에서 다시 버튼을 눌러 완료한 날짜 다음부터 이어서 생성합니다.
파일이나 API 키가 바뀌면 새 작업으로 시작합니다. 전체 대상 날짜가 완료되어야 다운로드 버튼을 표시합니다.

출력은 한글 XML 문서(.hml)입니다. 확장자만 .hwp로 변경하지 마세요.
사용 중인 한글 버전에서 파일 열기, 편집, 저장, 인쇄 페이지 나눔을 최초 1회 확인하세요.
참고 문서를 바꿔도 출력 표는 `template.hml`에 등록된 양식을 사용합니다.
주안 표를 텍스트로 읽으므로 요일 연결과 반복 기호 해석은 반드시 확인하세요.
활동의 세부내용·활동방법·발화는 동일 활동의 원문을 우선 보존합니다. 상세 계획이 없으면 주안의 중점 활동에 목표·자료·방법·교사 발화를 제안 계획으로 작성합니다. 일상 보육의 빈칸은 `routine_plans.json`의 기본 계획으로 보완합니다. 공식 세부내용은 첨부 자료에서 확인된 문구만 사용하도록 지시합니다. 실제 기록이 없는 평가는 빈칸으로 남기며, 미래형 지원 계획으로 대신 채우지 않습니다. 평가는 주안 원문과 문장 일치 여부를 검사하지만 날짜·활동 연결은 사용자가 확인해야 합니다.
템플릿의 반 이름, 결재란, 출결 등 고정 항목은 필요한 경우 한글에서 수정하세요.

문서 내용은 Google Gemini로 전송됩니다. 아동 이름 등 개인정보를 지운 자료를 사용하세요.
암호·배포용 문서와 HWPX는 지원하지 않습니다. 한글에서 일반 HWP로 저장해서 올리세요.

## 로컬 실행 및 검증

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
python -m unittest discover -s tests
```

`make_template.py`는 Windows와 한글이 설치된 PC에서 양식을 다시 만들 때만 사용합니다.
재생성 시 입력 자리 누락을 검사하며, 배포 전에 테스트를 다시 실행하세요.

설정 참고: [Streamlit Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management)
